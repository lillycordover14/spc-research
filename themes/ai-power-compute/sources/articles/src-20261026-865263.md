Unifying enterprise context and semantics: LookML in Knowledge Catalog is now GA
October 26, 2026
Maire Newton
Outbound Product Manager, Google Cloud
Ramanan Balakrishnan
Group Outbound Product Manager, Data Cloud
As enterprises go from experimental AI agent prototypes to using them in production, data teams are realizing that 
access
 to data is not the same as 
understanding
 that data. To help bridge that gap, today, we are announcing the general availability (GA) of LookML semantic language indexing in Knowledge Catalog for 
Looker Core on Google Cloud
.
To answer a complex business question accurately, an AI agent needs context — table schemas, data lineage, governance policies, business definitions, etc.. However, context is not a monolith; knowing where data lives is very different from knowing how to calculate metrics with it. In the enterprise, teams often conflate broad organizational context (usually in the form of metadata from structured and unstructured documents) with deterministic business semantics (the exact SQL formulas, join paths, and filtering rules that define metrics like net revenue or churn), assuming that a single data catalog or a business intelligence (BI) tool handling both enterprise-wide asset discovery and precise metric calculation.
In reality, no one tool can carry the entire load for agentic AI, as enterprise agents require both organizational context and deterministic business semantics. In Google Cloud environments, those are provided by Knowledge Catalog and LookML:
Broad enterprise context with Knowledge Catalog:
 Agents need a unified context graph that aggregates metadata across structured tables and unstructured documents. Through Knowledge Catalog, agents discover assets, inspect data quality, trace end-to-end lineage, respect column-level privacy tags, and surface corporate policy documents. The context graph tells an agent what data exists, how it is governed, and how it is connected.
Deterministic mathematical semantics with LookML:
 What a catalog does not author on its own is how the numbers are computed. Describing a table is not the same as defining how tables join or how metrics are calculated. Looker's modeling language, LookML, encodes production-tested semantic logic — multi-grain join protections, conditional filters, and exact KPI formulas — so agents don't guess SQL math at runtime.
With this native integration, the LookML business logic that powers your trusted BI reporting is automatically indexed into Knowledge Catalog — giving Gemini Enterprise and custom AI agents both enterprise-wide discovery and deterministic BI semantics.
Why a context graph needs deterministic semantics
When an LLM agent connects directly to raw database tables — even when armed with basic table descriptions or a business glossary — it still has to infer mathematical relationships on the fly. Without explicit semantic rules, agents routinely fall into two traps:
Metric definition drift:
 Standard text-to-SQL agents can invent conflicting formulas for foundational KPIs like net revenue or customer acquisition cost, failing to apply domain-specific accounting rules (such as recognizing revenue only when 
order_status = 'Complete'
 or prorating annual contracts across active service days).
Naive join fan-outs:
 Complex schemas often contain one-to-many (1:N) and zero-to-many (0:N) relationships across invoices, line items, and refunds. Without pre-modeled join relationships and symmetric aggregation rules, agent-generated SQL can multiply rows and inflate financial totals.
Knowledge Catalog and Looker solve this together, enabling you to model once in LookML and access those semantics everywhere across Google Cloud's AI ecosystem. Knowledge Catalog enforces semantic math when that logic is defined in a semantic modeling tool; LookML provides a mature, production-proven language for defining those exact mathematical relationships.
What's new: LookML in Knowledge Catalog
Previously, catalog integrations only captured shallow, file-level pointers and basic dashboard inventories. With this release, LookML's deterministic semantics become a first-class layer in the Knowledge Catalog context graph. An agent that finds a metric in the graph now also finds its exact definition, its join path, and its lineage back to source tables — in the same place, under the same governance. Synchronization is always on by default with no action required from end users, and with live sync, any update pushed to production LookML is reflected in Knowledge Catalog in near-real-time so agents operate on the freshest business logic.
Because this metadata is indexed directly into Knowledge Catalog by default, it is 
immediately available to Gemini Enterprise
, without custom agent code or separate catalog data stores. When connected to Knowledge Catalog, Gemini Enterprise uses built-in read-only skills and hybrid search to look up technical schemas, business glossaries, and indexed LookML logic in a single step, passing that rich context directly to your federated BigQuery connector to generate accurate SQL. (For developers building custom agents, the same context bundles are also accessible via the LookupContext API.)
Knowledge Catalog now captures and links the following entity levels across Looker Core on Google Cloud:
LookML models (looker-model):
 Captures descriptive metadata, database connection routing, include hierarchies, data validation tests (assert), and parent-child EntryLinks mapping models to their associated Explores, Views, and LookML dashboards.
LookML Explores (looker-explore):
 Indexes full relational join logic (type, sql_on, relationship cardinality such as many_to_one fan-out protection, foreign_key, required_joins, and sql_where) as Schema-Join relationships. It also captures mandatory filter guardrails (always_filter, access_filter), inherited dimensions and measures, and predefined 
starter queries
 that help agents and analysts overcome the cold-start problem.
LookML Views and fields (looker-view):
 Extracts column-level compiled LookML SQL expressions (for example, ${total_revenue} / NULLIF(${count}, 0)), primary keys, dimension group timeframes, field synonyms, and derived table transformation logic (including SQL and native derived tables, partition keys, and cluster keys).
Dashboards, Looks, and tiles (looker-dashboard, looker-dashboard-element, looker-look):
 Catalogs both UI-created and LookML-defined dashboards and visualization tiles, complete with dashboard filters, chart types, ownership, and usage statistics. Users in Knowledge Catalog are able to see table- and column-level lineage from underlying BigQuery tables all the way to individual dashboard tiles, allowing data engineers to evaluate schema changes proactively, before disruptions occur.
Looker Core on Google Cloud automatically indexes resolved LookML models, Explores, Views, lineage, and dashboards directly into Knowledge Catalog.

Bringing LookML into Knowledge Catalog gives Gemini Enterprise (and your broader agent ecosystem) a single place to retrieve both broad organizational context and governance from Knowledge Catalog and explicit mathematical relationships and SQL definitions authored in LookML.

When you follow pattern 3 and pair Knowledge Catalog with Looker's semantic layer in an enterprise agent workflow, the agent moves from guessing at raw SQL to a governed, two-stage execution flow:
Context and governance discovery in Knowledge Catalog:
 Before touching any data, the agent searches Knowledge Catalog, verifies that the thelook_ecommerce LookML model is gold-certified, checks column-level governance tags, and maps the prompt to exact LookML dimensions and measures, converting natural language into structured business intent.
Deterministic semantic execution:
 Rather than having the LLM invent SQL on the fly, the agent grounds its SQL in LookML's exact mathematical definitions indexed in Knowledge Catalog and returns trusted, repeatable figures.
Alongside the answer, the agent returns an interactive 
Open in Looker Explore
 link with the exact measures and filters pre-populated, letting users slice, dice, and inspect row-level line items in a single click.

Scaling agents for BI and the enterprise
A common question from data leaders is: 
"If we use Looker Conversational Analytics, when do we use an enterprise agent grounded in Knowledge Catalog?"
The two experiences are designed for complementary jobs across your organization:
Looker Conversational Analytics is your dedicated BI assistant:
 When business users are working inside BI workflows and asking questions scoped to a focused set of curated Looker Explores, Conversational Analytics delivers immediate, self-service data exploration and visualization directly within Looker.
Knowledge Catalog + Looker powers your enterprise-wide agents:
 When users ask questions in Gemini Enterprise across federated Data Cloud sources like BigQuery, they often span structured tables, BI metrics, and unstructured documents. Enabling Knowledge Catalog in Gemini Enterprise gives the assistant built-in skills to dynamically discover relevant semantics across hundreds of LookML models, pass indexed LookML join definitions, metric SQL formulas, and starter queries to the BigQuery connector to prevent join hallucinations, and enforce centralized governance aspects and IAM.
Getting started
Because Looker Core on Google Cloud, Knowledge Catalog, and Gemini Enterprise are natively integrated, you can connect your existing LookML business logic to your enterprise AI assistant in just a few clicks, with no custom agent code required.
To start discovering Looker semantics and grounding your agents:
Confirm first-party metadata indexing is enabled for Looker Core on Google Cloud.
 This is enabled by default for new instances, with no additional charge for storing Looker technical metadata. Once enabled, metadata synchronization into Knowledge Catalog is always on by default (across both initial indexing and ongoing live updates). Enable the Cloud Dataplex API and Data Lineage API in your project and grant users the required view roles (roles/dataplex.viewer, roles/looker.schemaViewer, and roles/datalineage.viewer) to have your resolved LookML models, Explores, Views, join paths, and dashboards automatically sync into Knowledge Catalog.
Enable Knowledge Catalog in Gemini Enterprise
. When you attach a BigQuery (or Spanner, Cloud SQL, or AlloyDB) data store in federated query mode to your Gemini Enterprise app, the Knowledge Catalog integration is enabled automatically. You can also turn it on or off at any time in the Google Cloud console by opening your Gemini Enterprise app, navigating to Configurations > Assistant, toggling on Enable Knowledge Catalog, and clicking Save and publish.
Ask questions
. Gemini Enterprise connects to Knowledge Catalog using end-user credentials, meaning users only discover and query data assets they have IAM permission to view (such as roles/bigquery.dataViewer). Behind the scenes, the assistant automatically looks up your indexed LookML definitions, join logic, and starter queries in Knowledge Catalog and passes them to your federated connector to deliver accurate, governed answers.

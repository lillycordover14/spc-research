Abstract
Looped language models (LMs) increase effective depth without increasing parameter count, but decoding latency and KV cache memory scale linearly with the number of loops. Speculative Decoding (SD) drafts tokens cheaply along the token dimension and verifies them in parallel using the target LM. Looped LMs, however, expose two axes of speculation, tokens and depth. We exploit this fact and propose 2DSD, a two-dimensional SD method designed for looped LMs. It combines block drafting at early-loop readouts with overlapping loop execution while preserving the model’s greedy outputs and sampling distribution. To further improve throughput, we integrate last-loop KV cache sharing to reduce KV cache read traffic, applying lightweight self-distillation where needed to maintain model quality. Across different looped LMs, 2DSD achieves geometric mean throughput speedups of up to 7.6× for greedy decoding and 5.5× for sampling over native AR. 2DSD sustains speculation gains at long context and across hardware platforms, and reduces KV cache storage while preserving model quality. Overall, 2DSD solves two critical issues in looped LMs (KV cache memory and low throughput) and makes effective-depth scaling at a fixed parameter count practical for inference.

Looped language models reuse the same Transformer weights over several loops, buying effective depth without adding parameters. The catch is at inference time: an ordinary autoregressive decoder makes every token wait through all the loops in sequence, repeatedly reading weights and keeping a separate KV cache for each loop, so both latency and cache size grow roughly with the loop count. 
[p
1
]
 That matters most when memory limits which model you can serve. The paper's method, 2DSD, drafts a block of future tokens from an early-loop prediction while other tokens keep moving through later loops, lets loops reuse the KV cache for committed history, and uses the final loop to verify what is kept. The payoff is higher decoding throughput.

Average speedup over native autoregressive decoding under greedy decoding, averaged across benchmarks, for DFlash, LoopSpec and 2DSD on Ouro-1.4B-Thinking, Ouro-2.6B-Thinking and Dory1.0-4B. The printed geometric means are 4.79×, 4.70× and 3.00× for DFlash; 2.38×, 2.52× and 2.13× for LoopSpec; and 5.73×, 7.64× and 4.50× for 2DSD.

On Ouro-2.6B-Thinking with greedy decoding, 2DSD reaches a 7.64× geometric-mean speedup over native autoregressive decoding, versus 4.70× for DFlash and 2.52× for LoopSpec.

 The geometric mean is taken over speedup ratios against native decoding across seven benchmark categories, not over raw token rates, and it excludes capped responses with highly repetitive endings.

Two axes, one schedule

Speculative decoding means a cheap drafter proposes tokens and the target model verifies them. In a looped model there are two places to speculate. One is depth: an early-loop readout can start work on the next token before the current token finishes its loops. The other is the token axis: a block drafter proposes several future tokens in parallel. The nearest prior work on the depth axis is 
LoopSpec
, which overlaps tokens using early-loop readouts but drafts one token at a time, so its gain is bounded by the loop count. The parallel block drafter comes from 
DFlash
, which has no loop-depth overlap. 
[p

 2DSD combines the two.

Share the history, keep the boundary

For KV caching, committed history uses last-loop KV entries shared across depths, while recent in-flight tokens keep their per-loop entries so concurrent work need not wait for them to finish all loops. This shrinks the cache and lets queries at different depths read the history bank in one attention call. 
[p
5
]
 On Ouro-2.6B-Thinking at 16K context, peak GPU memory is 35.3 GB for native decoding and 21.4 GB for 2DSD, with committed KV falling from 27.4 GB to 7.1 GB. 2DSD still uses 2.6 GB more than DFlash+Shared-KV and 4.4 GB more than LoopSpec+Shared-KV, though at higher throughput; its "Other" memory includes extra allocator reservations for CUDA graphs. 
[p
8
]
 Sharing alone is not the main source of the speedup: removing it changes 2DSD's mean throughput only modestly (3–10%).

Depth without the same toll

By overlapping future-token work with loop computation and serving committed history from one shared cache, 2DSD loosens the tie between effective depth, token latency and KV-cache growth.

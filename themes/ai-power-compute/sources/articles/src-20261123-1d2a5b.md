Sr. Software Engineering Manager, AlloyDB Omni

Open models like Gemma 4 from Google DeepMind are a great option to keep your data local. But how can a local AI model integrate with on-premises data?

AlloyDB Omni
, Google’s 100% PostgreSQL-compatible database that runs anywhere, now integrates with locally hosted large language models (LLMs). With AlloyDB Omni, you can build agentic experiences on your own infrastructure and on your own terms. Whether it’s in the cloud, in your datacenter, or even on your laptop, you can have data plus AI anywhere.

Built-in AI for your local environment

AlloyDB Omni is a downloadable, run-anywhere edition of AlloyDB that easily deploys to your own infrastructure, including on-premises. AlloyDB Omni packs powerful, built-in AI, including the same ScaNN indexing technology powering Google Search. When you pair AlloyDB Omni with a model, you can store vector embeddings at scale; search them semantically; and even query the database using natural language. You can use virtually any model you like, whether that’s a frontier Cloud-hosted model like Gemini or a local model. And with locally hosted models you maintain complete control over your data environment.

Connecting to Gemma 4, Qwen3.8, and other local models

You can now connect AlloyDB Omni to local models like 
Gemma 4
 and 
Qwen3.8
. No matter which model you choose, the architecture remains the same.
AlloyDB Omni calls a local model server directly from SQL — keeping prompts, data, and responses inside your environment.
This setup enables entirely new use cases for environments that were previously blocked from adopting agentic capabilities. If you operate an air-gapped network or have data locality requirements, you can still build intelligent applications. You can analyze local logs, generate summaries of proprietary internal documents, and power localized chatbots—all while maintaining strict data governance.

Keep data on-premises:
 Because the database and the model sit in the same local environment, your data never crosses the public internet.

Reduce latency:
 Processing inference requests locally minimizes network transit time.

Query directly via SQL:
 Your standard database queries can invoke machine learning functions that process data locally. Like this:

SELECT customer_name,
       ai.generate('Summarize in 1 short sentence: ' || comment,
                   model_id => 'gemma4_llm') AS summary
FROM customer_feedback;

Get started

You can test this integration on your own machines today. Using a Kubernetes environment we will show you how to deploy and integrate AlloyDB Omni and a local open model.

In this example, we will use Google Kubernetes Engine (GKE) to host the AlloyDB Omni database and local model. GKE gives us a standardized, reproducible environment but you can use the same setup on-prem or almost anywhere.

Step 4: Register the model with AlloyDB Omni

Connect to your database.
Loading...
kubectl exec -it -n ai-demo $(kubectl get pod -n ai-demo -l alloydbomni.internal.dbadmin.goog/task-type=database -o jsonpath='{.items[0].metadata.name}') -c database -- env PGPASSWORD="VeryStrongPassword" psql -h 127.0.0.1 -U postgres
Note: If you receive a connection error, you might need to wait a moment for your database to provision.

Now you should be connected to your AlloyDB Omni database with the 
psql
 client. Next, run the following SQL script to register your local model.
Loading...
CREATE EXTENSION IF NOT EXISTS google_ml_integration;
ALTER SYSTEM SET google_ml_integration.request_timeout_in_seconds = 600;
SELECT pg_reload_conf();
CREATE OR REPLACE FUNCTION google_ml.ollama_llm_input_transform(
  model_id character varying, prompt text,
  generation_config json, system_instructions json
) RETURNS json AS $$
  SELECT json_build_object(
    'model', CASE model_id
               WHEN 'gemma4_llm'  THEN 'gemma4:12b'
               WHEN 'qwen3_8_llm' THEN 'qwen3.8'
             END,
    'messages', json_build_array(
      json_build_object('role', 'system', 'content',
        COALESCE(system_instructions->'systemInstruction'->'parts'->0->>'text',
                 'You are a helpful assistant.')),
      json_build_object('role', 'user', 'content', prompt)
    )
  );
$$ LANGUAGE sql;

CREATE OR REPLACE FUNCTION google_ml.ollama_llm_output_transform(
  model_id character varying, response json
) RETURNS text AS $$
  SELECT trim(regexp_replace(
    response->'choices'->0->'message'->>'content',
    '<think>.*?</think>', '', 's'));
$$ LANGUAGE sql;

CALL google_ml.create_model(
  model_id => 'gemma4_llm',   -- and/or 'qwen3_8_llm',
  model_request_url => 'http://ollama-service.ai-demo.svc.cluster.local:11434/v1/chat/completions',
  model_provider => 'custom',
  model_type     => 'llm',
  model_in_transform_fn  => 'google_ml.ollama_llm_input_transform',
  model_out_transform_fn => 'google_ml.ollama_llm_output_transform'
);
Note: If you receive a 
Resource not found
 error, wait a moment for the model to load.

In addition to registering your model, the above script tells AlloyDB Omni how to interpret the model’s raw output. In this example chain-of-thought (CoT) reasoning is part of the response inside 
<think></think>
 tags. We don’t want the CoT, so our output transform function removes it.

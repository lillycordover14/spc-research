[agent notes, not verbatim] Primary Microsoft Copilot Studio blog post by Nitasha Chopra (VP and COO, Copilot Studio), dated May 26; year 2026 from page title.

Computer use: "Computer-using agents are now generally available". They interact with websites and desktop apps through the UI, useful for processes that lack APIs. New enterprise features: more secure credential management, model choice, automations that adapt to interface changes. Embedding computer-using agents in multi-step workflows is "now moving into preview".

Workflows: new experience "Now available in early release environments" with visual designer, agent nodes, AI-powered actions (classification, content generation, decision support) and node-level testing. Design philosophy: "structured where needed and adaptive where valuable".

Case study: Graebel built a Service Order Agent handling employee relocation requests arriving as unstructured emails, designed to scale across more than 30 service categories; reduced manual effort and faster turnaround reported without figures. "Graebel needed automation that could use reasoning, not just click."

Interop: new Work IQ REST API and CLI; remote MCP servers; "With agent-to-agent (A2A) communication now generally available in Copilot Studio".

Voice: real-time voice agents "now generally available in North America through Dynamics 365 Contact Center" with speech-to-speech; a voice agent governance guide released.

Orchestration layer in early release: Microsoft usage data (2026) shows "improving evaluation performance by approximately 20% while decreasing net token usage by 50%". Agent lifecycle visibility updates (generating, ready for testing, published, issues).

Pricing: not discussed. Related: Windows 365 for Agents (Cloud PCs for agents) in US preview per the May 1 Agent 365 post.

[agent notes] Read-through: computer use GA plus agent nodes in a workflow designer is the same design point RPA vendors moved to with 'agentic automation'. Microsoft bundles it into Copilot Studio, which already sits inside Power Platform licensing and Entra identity, so the incremental buying decision for a Microsoft shop is small. The Graebel example (unstructured relocation emails turned into service orders across 30+ categories) is a classic BPO-style intake process. No pricing, customer counts or accuracy rates were disclosed, so the economics versus RPA bots or BPO seats cannot be assessed from this page.

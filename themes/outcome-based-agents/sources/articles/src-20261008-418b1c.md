The Agent Economy Is Already Here
Today we’re announcing a $25 million Series A, bringing our total funding to $35 million. Since our January 2026 launch, we’ve seen 8x revenue growth and 5x more customers. But this post isn’t (just) about the round. It’s about why the round matters: the agent economy is arriving faster than anyone planned for, and it can’t scale without a security layer built for it.
The shift is no longer theoretical. According to IDC, 95% of companies now have AI agents deployed in production. Not in pilots or sandboxes, but in production, touching real customers, real data and real money. In addition, according to Gartner, the market for securing AI is projected to reach nearly $4.8 billion in 2027, up 68.7% from 2026, and nearly $7.7 billion by 2028.
The reason is simple. The promise of the agent economy rests on one idea: that companies can replace entire workflows with AI and capture substantial economic value by doing so. Onboarding, claims processing, customer support, procurement, research and code review are all being handed to agents that act on their own, around the clock, at a scale no team of people could match.
That value is only real if enterprises can trust what their agents do. Every workflow an agent takes over is a workflow that now runs without a human watching each step. Making that safe is what Rein exists to do. We don’t see ourselves as a brake on the agent economy. We see ourselves as what makes it possible.
Two AI Agent Security Problems, Arriving at the Same Time
In conversations with CISOs across financial services, healthcare, SaaS, retail and energy, we keep hearing about the same two challenges. They are different problems, but they are landing on security teams at once.
- Deploying agents safely. The agents enterprises build are given broad access to business systems, data and workflows. They read documents, call APIs, move records and trigger downstream actions automatically. More and more often, they act on instructions passed along by another system or another agent, not by a person. Security teams need to know what every agent is doing, govern what it’s allowed to do, and stop a harmful action before it executes, not after the incident review.
- Defending against adversarial AI. The same technology is now in attackers’ hands. AI-driven attacks probe, adapt and exploit at machine speed, far faster than a human team can triage alerts or ship a patch. When the attacker moves in seconds, the old sequence of detect, investigate, then fix breaks down. The model has to flip: block first, remediate afterwards.
Most security tools were built for one of these worlds, or for neither. Enterprises need both covered, in one place, at runtime.
AI Agent Security Risks Traditional Tools Can’t See
Here’s what surprises most security leaders: the biggest agent risks are invisible to the tools they already own. They don’t show up in a code scan, a posture dashboard or a gateway log. They live in the actions agents take at runtime, often several steps removed from anything a person asked for.
These are the risks we find every week:
- The PDF that wasn’t just a PDF. A global enterprise’s onboarding agent opened what looked like an ordinary document. Hidden inside was a prompt injection instructing the agent to act outside its intended role. Nothing about the file looked malicious to a person or a traditional scanner. Rein detected the out-of-role action and blocked it before any damage was done.
- The shopping assistant that could be turned. At Black Hat USA 2026, our research team, Agent Breakers, showed how we compromised the AI shopping agent of a major U.S. retailer. The agent was live, customer-facing and built by a sophisticated team. It still had a path to abuse that no existing control had flagged.
- Instructions from a machine, not a human. When one agent hands a task to another, the second agent often inherits trust it was never meant to have. A single poisoned input upstream can travel through a chain of agents and end as a real action, like a record changed, data sent or a transaction triggered, with no human in the loop to question it.
The common thread is that the risk isn’t in any single component. It’s in the behavior: what the agent actually does, why it does it, and whether that matches what it was built for. That’s the layer we watch.
What We’re Building: Runtime AI Agent Security for Enterprise Agents and AI Threats
Rein is the security layer for the agent economy. It protects the enterprise agents you build, and it stops the agents that attack your company.
We operate at runtime, at the exact point where an agent executes an action. That position lets us do things static tools can’t:
- See everything. Every action an agent takes is traced back to the line of code that triggered it and connected to its business outcome.
- Govern behavior. Security teams define what each agent should and shouldn’t do, and Rein holds it to that role.
- Block in real time. Harmful actions are stopped before they execute, including exploits for which no patch exists yet.
- Fix what matters. Rein prioritizes the issues that are actually exploitable and automatically generates fixes.
And we do this without routing company or customer data through a gateway or proxy. Security shouldn’t require you to reroute your business.
This is already working at scale. Rein secures thousands of AI agents executing millions of actions, for customers including Lemonade, whose services reach 3.31 million active customers, and Dun & Bradstreet, whose agentic products serve more than 240,000 customers.

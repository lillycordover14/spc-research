// Latent Semantic Memory for LLMs //
This paper presents some really interesting findings about agent memory.
They find that sixteen memory tokens beat full-context inference on FactKG while using 108x fewer tokens for the source documents.
Approach:
Documents are encoded once into reusable embeddings. For each query, a learned module gathers the relevant information from the whole collection and writes it into 16 tokens in the input space of a frozen LLM.
Results:
It beats Mem0, MemoRAG, and other baselines on five of eight benchmarks. On FactKG, it scores 84.33% against 80.43% with the full context.
It also works as agent memory. In TextWorld, using the agent’s own history as the collection raises success from 18.6% to 24.2%, and the agent revisits fewer rooms.
It also seems that it could help frozen LLMs accumulate and use knowledge effectively across long-context interactions. This is applicable to building continually learning AI systems.

On 18 October Elvis Saravia (@omarsar0) highlighted the paper “Memorilla: Latent Semantic Memory for LLMs” (arXiv 2610.21375, 15 October; Adibvafa Fallahpour, Jure Leskovec and co-authors). According to its abstract, the system writes information from a whole document collection into 16 query-specific memory tokens for a frozen LLM, beats baselines including Mem0 and MemoRAG on five of eight benchmarks, and on FactKG reaches 84.33% accuracy versus 80.43% with full-context inference while using 108x fewer tokens to represent the documents. The TextWorld success figures in the post (18.6% to 24.2%) are the poster’s summary. We include it as a research data point on the memory layer Chase calls super, super early.

Horizontal Agents Calling Vertical Ones

The second clip opens: “My take on the consumer space is that you will have both horizontal and vertical agents, and the horizontal agents will interact with the vertical agents.”

Chase’s reason is what each app already knows. “A lot of these apps have knowledge about you and can learn things about how you interact with that app better than a general horizontal agent could,” he said. He went on:

“It is a better experience if there is an agent that wraps those APIs and exposes a natural language face for a horizontal agent to interact with.”

Stebbings’ notes put the same view as: “Most apps should have a vertical agent because they can learn more about how a user interacts with them than a general agent can.”

Why the Harness Has to Stay Neutral

The notes link memory to a second argument, about the harness that connects a 
model
 to a company’s data and tools. “Companies want to be able to switch models, but the harness can be tightly tied to a 
model
, and context today is intricately linked to the harness,” they say.

They continue: “If memory is built in a way that is linked to the harness, and the harness is linked to the 
model
, the company ends up stuck.”

LangChain’s own About page says its commercial platform, LangSmith, gives companies 
control
 over “the layers that matter, like models, context, and deployment,” and that its newest 
product
 is an agent harness called Deep Agents.

What Agents Cost LangChain

The notes also give a figure for LangChain itself: it “spends roughly 30% of its engineering salary on coding tools, a share that has fallen over the last two months even as token usage has gone up.”

On large customers, the notes say: “Cost has risen as a concern for large enterprises, though it still ranks below accuracy and above latency.”

LangChain’s About page says it has crossed 1 billion open source downloads and ingests over 1 billion events per day on LangSmith.

AI agents built with LangChain can reason, select tools, and act on behalf of users, but they do so without any built-in decision layer governing which model handles a request or whether a dangerous tool call should proceed. Building a safer AI agent harness with Jev and LangChain addresses this gap directly.

Jev provides a typed, Pydantic-modeled decision framework that slots into the LangChain agent loop, enabling developers to route requests to cheaper models for trivial tasks and gate sensitive tool calls behind explicit risk approvals. This tutorial walks through building that harness from scratch: a structured system that enforces guardrails without stripping the agent of its autonomy.

Wrapping Up

Why AI Agents Need a Decision Layer

LangChain agents follow a fixed loop with no branching logic: the LLM reasons about a query, selects a tool, executes it, observes the result, and repeats until it has an answer. The problem is that this loop treats every request identically. A user asking "What is your refund policy?" hits the same GPT-4-class model as a user requesting a complex multi-step workflow. That burns budget on inference a smaller model could handle just as well -- gpt-4o-mini costs roughly 1/30th per input token compared to gpt-4o (check OpenAI's pricing page for current rates). Worse, a tool call like 
delete_user_account
 executes with the same lack of friction as 
search_faq
, meaning a single hallucinated function call can trigger irreversible side effects with no programmatic checkpoint.

These two failure modes, cost waste and unsafe execution, stem from the same root cause: decisions about model selection and tool permissions are implicit, buried in prompts or absent entirely. An AI agent harness is a typed decision layer that wraps the agent loop, introducing explicit, auditable decision points. The goal of this tutorial is to build a harness that routes requests by complexity to appropriate model tiers and requires pre-execution approval for sensitive tools.

Note on cost overhead:
 The router and gate each add one LLM call per request. Net cost savings only occur when routing overhead is offset by diverting enough requests away from expensive models to recoup the extra tokens. Measure your per-request routing cost against your per-request model cost delta to find your break-even volume. For low-volume deployments, the overhead may exceed savings.

The tech stack: Python, LangChain, Jev, Pydantic, and langchain-openai.

Architecture Overview

The Standard LangChain Agent Loop

In a typical LangChain agent, the cycle flows from LLM reasoning to tool selection, tool execution, observation, and back to the LLM. The developer fixes model choice at initialization and, at best, bakes tool permissions into the system prompt as natural-language instructions the LLM can ignore. The loop enforces no typed contract and leaves no audit trail for why a particular tool was invoked or why a particular model was used.

Adding Jev Decision Nodes

Jev introduces two explicit decision points into this loop, each modeled as a Pydantic-typed decision node that produces a 
structured, typed, auditable output
:

Request Router:
 Classifies the incoming request's complexity and selects an appropriate model tier. A simple FAQ lookup gets routed to 
gpt-4o-mini
; a complex, multi-step operation gets routed to 
gpt-4o
.

Tool Gate:
 Evaluates the proposed tool call against a risk policy before execution. Low-risk tools proceed automatically. Medium-risk tools proceed with a logged warning. High-risk tools are denied and escalated.

Each node replaces ad-hoc if/else logic with a structured, version-controllable decision that can be logged, tested, and reviewed independently of the agent's reasoning.

Architecture Flow

The flow works as follows: an incoming request first passes through the Request Router (Jev), which classifies complexity and selects a model. That model powers the LLM reasoning step, which proposes a tool call. Before execution, the proposed call passes through the Tool Gate (Jev), which evaluates risk and returns one of three outcomes: approve, log-and-approve, or deny. If approved, the tool executes, and the observation feeds back into the LLM loop. If denied, a refusal message returns to the agent, which can rephrase or escalate.

The decision logs from each Jev node provide structured records: what was classified, why, what model was used, which tool was proposed, and whether it was approved or denied. For a production audit trail, persist these structured outputs to an observability platform rather than relying on stdout.

Best Practices and Next Steps

Agent Guardrails Beyond the Basics

Rate limiting per tool prevents abuse even for approved operations. If 
update_user_profile
 is approved but called, for example, 500 times in a loop due to an agent reasoning error, a rate limiter catches the anomaly. Persist decision logs to an observability platform such as LangSmith or Datadog so the harness doubles as a monitoring surface. Version your Pydantic decision models alongside agent code so that policy changes are tracked in source control.

Extending the Router

Cost tracking per model tier is a natural extension. Record which model was selected for each request and its token usage, and teams can measure actual savings from routing simple queries to cheaper models. Historical classification data can also feed back into the routing prompt to improve accuracy over time without changing the decision schema.

Human-in-the-Loop Escalation

For 
high
 risk denials, the harness can push an approval request to Slack, an internal dashboard, or a ticketing system. The agent loop pauses, and execution resumes only after a human confirms or rejects the operation. This turns the denial from a dead end into a workflow, keeping the agent useful while maintaining safety for irreversible operations.

The rule-based hard deny-list ensures that truly irreversible operations are blocked deterministically, independent of LLM judgment.

Wrapping Up

Separating open-ended LLM reasoning from fast, typed decisions gives AI agents typed routing and deterministic gating -- cheaper when routing volume justifies overhead, safer via deny-lists and typed gates. Jev and Pydantic provide structured, version-controlled decision points that enforce routing and risk policies through typed output contracts. LangChain provides the agent loop and tool-calling infrastructure. Together, they supplement prompt-based reasoning with structured, testable, and observable decision nodes. The rule-based hard deny-list ensures that truly irreversible operations are blocked deterministically, independent of LLM judgment. Start by replacing the stub tools with your production API calls, adding your deny-list entries, and wiring decision logs to your observability stack.

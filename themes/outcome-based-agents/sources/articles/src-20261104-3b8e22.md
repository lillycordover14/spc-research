Safari Gets Vertical Tabs in iOS 27.3 Beta [2026]

 

Dr. Elena Marchetti

Updated Nov 4, 2026 · 17 min read

 

 
Apple is adding Vertical Tabs to Safari in iOS 27.3, iPadOS 27.3, and macOS 27.3, and 
TechRadar reports
 that the same release brings a new Adaptive Dark Mode for websites that ship without a native dark theme. The reported beta date is November 3, 2026. That makes Safari vertical tabs the first thing many developers will want to test this week.

The pairing is more useful than it sounds. A sidebar of tabs fixes the cramped top bar that plagues anyone with 30 open pages. A one-tap dark conversion fixes the white flash that hits your eyes at midnight when a documentation site ignores your system theme. Both changes target daily friction rather than headline features, and both landed in a point release instead of a major version.

What Apple added to Safari in the 27.3 beta

The confirmed list is short and specific. Vertical Tabs arrives across iOS 27.3, iPadOS 27.3, and macOS 27.3. Adaptive Dark Mode arrives in the same releases. On iPhone, you can switch Vertical Tabs on through Settings, then Apps, then Safari. When Dark Mode is on and Safari spots a compatible bright website, it shows a Try option that builds a darker version of the page.

Apple has not confirmed a final public-release date for any of the three operating systems. It has not confirmed a price, a subscription fee, or a hardware requirement either. Some outlets point toward December. Macworld and 9to5Mac both describe a December 2026 general release as expected, but that is their read of the usual beta cycle and not an Apple commitment. Treat it as a planning assumption, not a date.

The timing also matters. A 27.3 beta is the kind of release that usually carries bug fixes and small refinements. Safari vertical tabs: how the layout works

Safari vertical tabs move your open tabs from a strip across the top to a bar along the left edge of the window. According to 
MacRumors
, the bar shows icons by default to save space, and you can expand it to read full page titles. The same report says the feature works on iPhone, iPad, and Mac, and that it integrates with Topics, the automatic sorting that relies on Apple Intelligence, as well as with Tab Groups.

Pinned tabs keep working, and you can still switch between Tab Groups the way you do today, per the MacRumors write-up. That detail matters because it shows Apple built the sidebar on top of existing organization tools instead of replacing them. If you already sort research into groups, the vertical layout is a new view of the same structure.

The icon-first design is a deliberate trade. A horizontal strip gives each tab a shrinking slice of width, so titles collapse into unreadable stubs once you pass a dozen pages. A vertical bar stacks tabs by height, which scales better with a long list. Expanded titles cost horizontal space, and icons alone force you to recognize sites by logo. Which mode feels better will depend on your screen and your habits.

How to turn on vertical tabs on iPhone, iPad and Mac

The iPhone path is confirmed: open Settings, choose Apps, choose Safari, and enable Vertical Tabs. 
9to5Mac
 adds that on Mac and iPad the option sits in the View menu, while MacRumors says it can also appear in Safari preferences. Because this is a beta, the exact menu wording may shift before release.

Quick setup checklist for beta testers

Install the iOS 27.3, iPadOS 27.3, or macOS 27.3 developer beta on a secondary device first.
On iPhone, open Settings, then Apps, then Safari, and switch on Vertical Tabs.
On Mac and iPad, look in the View menu inside Safari.
Expand the sidebar once to confirm page titles appear for your most-used sites.
Pin the three or four pages you open every day, then test a Tab Group switch.

A word of caution for work machines. Beta system software can break managed profiles, VPN clients, and developer toolchains. If your Mac is your only build machine, wait for a later beta or the public release. The Safari features are not worth a broken Xcode setup.

Adaptive Dark Mode: what the Try option does

Adaptive Dark Mode targets a long-running annoyance. Your phone or Mac sits in dark mode, but plenty of websites still render a bright white page. Safari now detects a compatible bright site while Dark Mode is active and offers a Try button. Tap it and Safari generates a darker rendition of the page on the fly.

You keep control after that first test. Based on the confirmed details, Adaptive Dark Mode can run automatically for compatible websites, or you can configure it site by site. That split suits different habits. Some people want every bright page darkened without a prompt. Others want it only on the three blogs they read at night and nowhere near a design tool where color accuracy matters.

MacRumors reports that the system works by darkening the background, changing text contrast, inverting logos and graphics, recoloring vector artwork, lifting raised surfaces, and rebalancing layered shadows. That list reads like a checklist of everything that breaks when a tool simply inverts a page’s colors. Apple is attempting a themed conversion, not a blunt filter.

Which sites Adaptive Dark Mode skips

Adaptive Dark Mode does not touch every page. Websites with an existing native dark appearance, or a design that is already sufficiently dark, are excluded. That rule protects sites that took the time to ship a proper dark theme. It also avoids the double-darkening problem, where a converter turns an already dark page into near-black mud.

MacRumors also reports that developers can add metadata to stop Safari from applying the feature. The report does not specify which metadata, so no one should assume a particular tag or attribute yet. Web teams should wait for WebKit documentation and Apple’s developer release notes before they ship an opt-out.

9to5Mac’s coverage does not mention a developer opt-out, which is a reminder that these details come from early beta reporting. Outlets can differ on small points while a beta is new. Where sources disagree, the safest reading is that the opt-out exists but is not yet fully documented.

Does it work on any website? Not quite

TechRadar’s headline says Safari gets a way to make any site dark. The confirmed wording is narrower. Adaptive Dark Mode applies to websites that lack native dark-mode support and that Safari judges compatible with the feature. So the accurate description is that it works on many bright sites, not literally all of them.

The gap between many sites and any site is not trivial. Pages built on canvas, heavy WebGL, embedded video players, or unusual color systems can resist automated conversion. Photography portfolios and design tools often depend on exact colors, and a darkened rendition could distort them. Apple’s compatibility check exists for those cases, and the Try prompt gives you a manual preview before you commit.

Readers should also not expect the feature to rewrite pages permanently. It changes how Safari renders a site on your device. The site itself, its HTML, and its stylesheets stay untouched. That is why a per-site setting makes sense, since you can turn it off for a page that looks wrong without any effect on other visitors.

Why this matters for developers and web teams

For anyone who builds websites, Adaptive Dark Mode is a rendering behavior to test, not just a user convenience. If your site has no dark theme, Safari may soon offer visitors a darkened version without asking you. That can help users, and it can also produce odd results if your branding relies on specific colors or your images assume a white backdrop.

Test your own pages in the beta

Open your production site in the 27.3 beta with Dark Mode on and see whether Safari shows the Try prompt. Tap it and review logos, charts, code blocks, form fields, and any SVG icons. Look for transparent PNGs that now sit on a dark background with a glowing edge. Check screenshots in documentation, since those often carry baked-in white margins.

Ship a real dark theme if you can

The standards-based route still beats any automatic conversion. The prefers-color-scheme media query lets a stylesheet respond to the user’s system setting, and the color-scheme property and meta tag tell browsers which themes a page supports. Apple’s exclusion rule means a site with a sufficiently dark native appearance skips the feature, so a hand-built theme protects your design intent. Check the WebKit release notes for how the new feature treats these signals before you assume anything.

Historical context: from Arc to Apple

Vertical tabs spent years as an enthusiast feature. Power users argued that a sidebar suits widescreen monitors better than a strip across the top, since screens have more horizontal room than vertical room. Arc turned the idea into a signature design. According to 9to5Mac, that browser is now discontinued, which leaves a gap among people who liked its sidebar workflow.

Apple’s own tab history moved in steps. Safari added Tab Groups to organize related pages, and recent releases layered Apple Intelligence sorting on top through Topics. Vertical Tabs is the next logical piece, a layout that makes those organizing tools more visible. MacRumors says the new bar works with both Topics and Tab Groups, which suggests Apple planned the pieces to fit together.

Dark mode followed a similar path. Apple introduced system-wide dark mode years ago, and websites adopted it unevenly. Many large sites support the user’s system theme, while small blogs, older documentation, and internal tools often do not. Browser extensions filled the gap for years. A native option inside Safari removes an install step and, importantly, a third-party extension’s access to every page you visit.

Market impact: extensions, rival browsers and the 27.3 timing

Nobody has published adoption or revenue figures for these features, so any hard market-size claim would be invention. The directional effects are easier to reason about. Dark-mode extensions face a built-in competitor on Apple platforms. Developers of tab-management extensions for Safari face the same. Both categories rely on gaps in the browser, and Apple just narrowed two of them.

Rival browsers on Apple hardware also feel pressure. On iPhone, browsers have largely relied on Apple’s WebKit engine, so a Safari feature that improves day-to-day use raises the baseline other apps are judged against. Users who tried a third-party browser mainly for its tab sidebar now have a reason to look at the default again. That is an inference from the product design, not a measured shift.

Siri gets tab and history controls

The Safari changes extend past layout and color. 9to5Mac reports that Siri can now manage tabs, with voice commands to move, organize, sort, and close them. MacRumors adds that Siri can clear browsing history for specific sites and time ranges. Both outlets say Siri’s ability to understand full webpage content, not just what is visible on screen, is planned for later betas.

This pairs naturally with the new sidebar. A long vertical list is easier to read but still tedious to prune by hand. Asking Siri to close every tab from one site, or to sort a pile of pages, turns the sidebar into something you can talk to. Voice control of browser housekeeping also helps users who cannot easily use touch or a mouse.

Privacy-minded readers should watch the page-content feature when it arrives. Letting an assistant understand an entire page raises questions about what leaves the device. Apple has not detailed that in the sources reviewed, so there is nothing to confirm yet. The later betas will say more.

Who should install the beta and who should wait

Casual users should wait. A beta can bring battery drain, app crashes, and features that change or disappear before release. If the only reason to install it is vertical tabs, the public release is a safer path, and Apple’s expected December window is not far off even though it is unconfirmed.

Web developers are the exception. Seeing how Adaptive Dark Mode treats your site before your visitors do is worth a test device. Designers and front-end teams should check their pages on at least one iPhone and one Mac running the beta, with Dark Mode on and the Try prompt exercised. That costs an hour and can prevent a wave of confusing support tickets.

Teams with managed fleets should hold off on rollout and let IT test the beta on a pilot group first. Enterprise web apps built on fixed color palettes are the most likely to look strange under automatic conversion. A pilot also reveals whether internal tools need the opt-out metadata that MacRumors says exists.

FAQ: Safari vertical tabs and Adaptive Dark Mode

When do Safari vertical tabs arrive?

The features appear in the iOS 27.3, iPadOS 27.3, and macOS 27.3 beta reported on November 3, 2026. Apple has not confirmed a final public-release date. Some outlets expect December, but that is an estimate.

How do I enable vertical tabs on iPhone?

Open Settings, choose Apps, then Safari, and turn on Vertical Tabs. On Mac and iPad, 9to5Mac says the option is in the View menu.

What does the Try button do?

When Dark Mode is on and Safari detects a compatible bright website, it shows a Try option. Tapping it creates a darker version of the page. You can then keep it automatic for compatible sites or configure it per site.

Does Adaptive Dark Mode work on every website?

No. The confirmed scope is websites without native dark-mode support that are compatible with the feature. Sites that already have a native or sufficiently dark look are excluded, so the claim that it works on any site is not confirmed.

Can website owners stop Safari from darkening their pages?

MacRumors reports that developers can add metadata to prevent it. The report does not name the metadata, so wait for official documentation before relying on a specific tag.

Will the features cost money or need new hardware?

Apple has not announced a price, a subscription fee, or a hardware requirement. Treat any claim of a limit as unconfirmed until Apple publishes compatibility details.

What else changes in Safari in this beta?

9to5Mac and MacRumors report new Siri controls for moving, sorting, and closing tabs, plus clearing history for specific sites and times. Siri’s ability to understand full webpage content is planned for later betas.

Should I install the beta just for vertical tabs?

Most people should wait for the public release. Web developers have a good reason to test early, since Adaptive Dark Mode can change how their sites look to visitors.

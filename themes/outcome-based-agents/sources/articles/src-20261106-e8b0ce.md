What Changed in the v1 Line

LangGraph 1.0 reached general availability on October 22, 2025, according to a LangChain resource page. A year later, the v1 documentation describes it as a stability-focused release that keeps the core graph APIs and execution model while improving type safety, documentation and developer ergonomics. That wording signals a runtime LangChain wants teams to build on for years, not one it plans to reshape every quarter.

The more visible change sits one layer up. LangChain v1 introduced 
create_agent
 as the standard way to build agents, and it replaces 
langgraph.prebuilt.create_react_agent
 as the recommended path. LangChain’s own materials call v1 a “production-ready foundation” centered on that function. The old prebuilt is deprecated, not retired, so existing code keeps running while the docs steer new projects elsewhere.

Fall 2026 brought a steady stream of smaller releases on top of that base. LangChain v1.4.0, highlighted in the October 2026 newsletter, added FastMCP support through the 
langchain.mcp
 namespace. The 
langchain-core
 package shipped v1.7.0 on October 22, 2026 with incremental 
tool-call-delta
 streaming events, replacing the old pattern of repeatedly sending accumulated tool-call arguments.

Version trackers report newer point releases. One tracker lists LangGraph 1.2.0 on October 14, 2026, with finer node execution controls such as timeouts, error recovery and graceful shutdown, plus a beta 
DeltaChannel
 that reduces checkpoint overhead. The same tracker lists LangGraph 1.2.19 on October 30, 2026, with fixes to tracing, event namespaces and tool-node streaming. Treat those numbers as reported, because LangChain’s official pages in our sources did not confirm them.

The legacy lines are the real deadline. LangChain 0.3 and LangGraph 0.4 stay in maintenance through December 2026. If your repository still imports from those versions, plan the upgrade now, because the support clock runs out just as most teams enter year-end change freezes.

Nothing in the November 2026 sources shows a rename, retirement or acquisition of LangChain, LangGraph or LangSmith. The confirmed changes concern positioning (LangChain as the easy on-ramp, LangGraph as the runtime) and billing, not product survival. That distinction matters if you read older blog posts that treat the two libraries as competitors.

How create_agent Sits on LangGraph

Think of the stack in three layers. At the bottom, LangGraph handles state, persistence and execution of a graph. In the middle, LangChain’s 
create_agent
 assembles a standard loop where a model decides, calls tools, reads results and repeats. At the top, your product code sets prompts, tools and guardrails. Because the middle layer compiles down to a graph, you can inspect or extend the result with LangGraph primitives.

The Default Path: One Function, One Loop

For most agents the default path covers the job. You hand 
create_agent
 a model, a list of tools and a system prompt, and you get a runnable agent. The loop, message handling and tool dispatch come prebuilt. This is the “easier high-level agent API” LangChain describes, and it removes the boilerplate that made early LangChain agents feel heavy.

from langchain.agents import create_agent
from langchain.tools import tool

@tool
def lookup_order(order_id: str) -> str:
    """Return the status of an order."""
    return f"Order {order_id}: shipped"

agent = create_agent(
    model="your-provider:your-model",
    tools=[lookup_order],
    system_prompt="You are a support agent. Use tools before answering.",
)

result = agent.invoke(
    {"messages": [{"role": "user", "content": "Where is order 1042?"}]}
)
print(result["messages"][-1].content)

The Escape Hatch: Write the Graph Yourself

Some workflows do not fit a single loop. A refund flow might require a model draft, a policy check, a human approval step that can wait hours, and a payment call that must never run twice. LangGraph lets you model each step as a node, wire the edges, and attach a checkpointer so the run survives restarts. The pause-and-resume pattern below uses LangGraph’s 
interrupt
 primitive.

from typing import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.types import interrupt, Command

class RefundState(TypedDict):
    amount: float
    approved: bool

def review(state: RefundState):
    answer = interrupt({"question": "Approve refund?", "amount": state["amount"]})
    return {"approved": answer == "yes"}

def pay(state: RefundState):
    return {"approved": state["approved"]}

builder = StateGraph(RefundState)
builder.add_node("review", review)
builder.add_node("pay", pay)
builder.add_edge(START, "review")
builder.add_edge("review", "pay")
builder.add_edge("pay", END)

graph = builder.compile(checkpointer=InMemorySaver())
cfg = {"configurable": {"thread_id": "refund-1"}}

graph.invoke({"amount": 80.0, "approved": False}, cfg)   # pauses at review
graph.invoke(Command(resume="yes"), cfg)                  # resumes later

Swap 
InMemorySaver
 for a database-backed checkpointer in production, otherwise a process restart loses the paused run. The point of the sketch is the shape: explicit state, explicit edges, and a pause that costs nothing while it waits. A prebuilt loop cannot express that cleanly.

What LangChain’s CEO Says About the Split

The clearest explanation of the split comes from LangChain’s co-founder and CEO, Harrison Chase, who has written about it on the company blog. Keep in mind that he speaks for the vendor, so read these statements as the intended design rather than as independent testing. Still, they show why the two libraries now coexist.

In 
a retrospective on the project’s first three years
, Chase wrote: “While langchain was the fastest place to get started, we traded power for ease of use.” In the same post he added: “LangGraph was inspired by the limitations of the initial langchain.” Read together, those lines admit that early LangChain hid too much, and that LangGraph exists to hand control back.

He repeated the contrast in a post on agent frameworks and observability, where he wrote: “langgraph was lower level and more flexible.” That sentence maps directly onto the specs table. Flexibility lives in LangGraph, and convenience lives in LangChain.

The most useful framing appears in a post separating frameworks, runtimes and harnesses. Chase wrote: “LangChain is an agent framework, LangGraph is an agent runtime, DeepAgents is an agent harness.” He then explained how the pieces connect: “Agent runtimes are generally lower level than agent frameworks and can power agent frameworks.” That is exactly the arrangement in v1, where the framework’s agent function rides on the runtime.

What should you take from this? First, the maintainers do not see the libraries as substitutes. Second, the three-way vocabulary (framework, runtime, harness) tells you where to look when something breaks: a tool-calling bug usually lives in your framework layer, while a lost checkpoint or a stuck pause lives in the runtime. Third, the vendor’s own admission about trading power for ease explains why many older tutorials push you toward LangGraph for anything non-trivial.

A caution on currency. Chase’s posts describe design intent, and the product names and version lines have moved since he wrote them. Use his terminology, but check the v1 documentation for current function names and signatures before you copy any code from older write-ups.

State, Durability and Human-in-the-Loop

LangGraph’s reason to exist is stateful, durable execution. LangChain’s documentation positions it for long-running agents, complex control flows, multi-agent orchestration and human-in-the-loop steps. When a run can take minutes or days, or when it must pause for a person, the runtime layer stops being an implementation detail and becomes the product.

Consider what durability buys. A checkpointer stores state after each step, so a crashed worker resumes from the last good node instead of replaying an entire conversation and re-calling paid tools. A pause at an approval node holds state without holding a process open. And because the graph is explicit, you can inspect which node ran, which edge fired and where a failure occurred.

The plain 
create_agent
 loop inherits much of this through its LangGraph base, but you shape it less. If you only need a model that calls tools until it finishes, the default behavior is fine. If you need a rule like “never call the payment tool twice” or “route legal questions to a different branch,” encoding that in graph structure is safer than encoding it in a prompt.

Operational detail shows how closely the community watches production behavior. LangChain’s forum carries a thread about a bug affecting thread-history and state-update requests on factory graphs in 
langgraph-api
, reported in October and described as fixed in versions 0.16.7 and later. Another thread, dated October 31, 2026, asks whether a checkpointer that accepts two concurrent writers should still score the top conformance level. Those are community-forum items, not formal announcements, but they show active scrutiny of persistence correctness.

Deployment follows the same logic. LangSmith Deployment, also called the Agent Server path, is infrastructure for LangGraph agents, and the LangGraph CLI builds and runs that server locally. The CLI documentation required 
langgraph-cli
 0.4.32 or later in late October 2026. On November 3, 2026, LangSmith made bring-your-own-cloud deployment generally available on AWS, with Azure and Google Cloud in beta, which matters for teams that cannot send agent traffic outside their own accounts.

Streaming, MCP and Tooling Updates This Fall

Streaming changed more than any other area in the last two months. LangChain’s November 5 post argues that agent streaming should move from raw token chunks toward application-level events, covering messages, tool calls and subagent status, and it says the work spans LangChain, LangGraph and Deep Agents. For a chat interface, that means your front end subscribes to meaningful events rather than parsing partial strings.

The change has a compatibility cost. LangChain’s guidance says that to read the new incremental tool-call streaming, you should upgrade 
langchain-core
 on the server to 1.7.0 or later together with 
langchain
 1.4.7 or later. On the client side, Python users need 
langchain-core

@langchain/vue

Observability and Evaluation: Where LangSmith Fits

Whichever framework you pick, you will want to see what the agent did. Agents fail in ways unit tests miss: a tool called with the wrong argument, a retrieval step that returned stale text, a loop that burned through tokens before giving up. LangSmith exists to capture those runs as traces, score them with evaluations and feed the failures back into your prompts and graphs.

LangChain lists the current commercial product names on its enterprise pricing page, dated November 2, 2026: Observability and Evaluations, Deployment, Deployment (Self-Hosted), Engine, Fleet, Sandboxes, Tuned Evals and Bulk Export. The first is the entry point for most teams. It records each model call, tool call and graph step, then lets you filter by failure, latency or cost.

Cost tracking got a meaningful upgrade in the first days of November. LangSmith began automatically recording token usage and derived costs for major model providers, and it lets you add custom cost data for tools, retrieval and other operations. The model-pricing page gained provider filtering and start-date sorting, with your selections preserved in the page URL. Teams that bill internal customers for agent usage will appreciate that detail.

The framework choice changes what you see in a trace. With 
create_agent
, a trace looks like a loop: model call, tool call, model call. With a hand-built graph, a trace follows your node names, so a failure reads “review node, approval timed out” instead of “model call 4.” That naming discipline pays off when a support engineer, not the original author, debugs the run at 2 a.m.

Evaluation deserves the same attention as tracing. The Numan example below describes an eval-first approach, meaning the team defined how it would judge the agent before shipping. You can do the same with either framework. Record 30 to 50 representative conversations, define pass and fail criteria, run them on every change, and block deploys that regress. At the metered rate of 0.015 LSU per evaluation run, a 50-prompt suite costs about $0.75 per full pass at list price.

Support is a separate line item. LangChain’s support page lists Base, Standard and Premium support plans for LangSmith, though the page text we retrieved does not show their prices. The same page says enterprise customers can receive support for LangChain, LangGraph and Deep Agents open-source issues, which matters if your legal team wants a named vendor behind the libraries your product depends on.

Finally, remember that tracing is optional. Both frameworks run without LangSmith, and you can send traces to other tools or log them yourself. The trade is convenience against independence. For a team of three shipping a first agent, the free Developer tier removes friction. For a regulated company, self-hosting or bring-your-own-cloud on Enterprise may be the only acceptable route, and AWS bring-your-own-cloud has been generally available since November 3, 2026.

Pros and Cons of Each Approach

Both libraries share the same strengths in ecosystem and license. The differences show up in control, learning curve and operating cost. Here is where each layer earns its keep and where it costs you.

LangChain 
create_agent
: pros

Fastest path from idea to a running tool-calling agent
Runs on LangGraph, so persistence and streaming come along
FastMCP support in v1.4.0 simplifies tool wiring
MIT license and $0 software cost
Clear upgrade path: you can inspect and extend the underlying graph later

LangChain 
create_agent
: cons

Less control over branching and step order than a hand-built graph
Safety rules often end up in prompts, which are easier to break
Older tutorials describe pre-v1 patterns that no longer match the docs
Fast release cadence demands version pinning

LangGraph: pros

Explicit state, nodes and edges make behavior testable
Durable execution, pauses and human approval are first-class
Stable v1 runtime with core graph APIs preserved
At least one year of maintenance promised for v1 after a 2.0 release
Suits multi-agent hand-offs and long-running jobs

LangGraph: cons

More code and a steeper learning curve for simple agents
Production persistence needs a real checkpointer and operational care
Easy to over-engineer a flow that a single loop would handle
Hosted deployment pulls you toward the paid LangSmith platform

The cons are mostly mirror images. LangChain’s convenience costs control, and LangGraph’s control costs code. Since one is built on the other, you rarely have to commit permanently. That flexibility is the strongest argument for starting at the top layer and descending only when the workload demands it.

Alternatives and Where Deep Agents Fits

LangChain now describes a third open-source piece, Deep Agents, as an agent harness. In Chase’s vocabulary, a harness packages opinionated defaults for long-horizon work on top of the runtime. Deep Agents is MIT-licensed like its siblings and appears in LangChain’s streaming and enterprise materials, and a managed version (Managed Deep Agents v0.8) reportedly added user-owned credentials, user-level memory and HTTP channels in September 2026.

That makes the practical menu three-deep rather than two. Use 
create_agent
 for a standard tool-calling agent, LangGraph for explicit control, and Deep Agents when you want a prebuilt harness for longer tasks. LangChain’s own enterprise page lists the commercial products around them: Observability and Evaluations, Deployment, Deployment (Self-Hosted), Engine, Fleet, Sandboxes, Tuned Evals and Bulk Export.

Outside the LangChain family, the field has shifted too. LangChain published a June 23, 2026 page titled “LangChain vs. AutoGen in 2026: What the Maintenance Announcement Changed,” which signals that the AutoGen project entered a maintenance posture. Because that page comes from a competitor’s vendor, verify the status on AutoGen’s own repository before you decide. Provider SDKs and cloud agent services from the major clouds offer other routes, though each brings its own lock-in.

Weigh lock-in honestly. The open-source frameworks are portable, but the smoother tracing, evaluation and deployment path runs through LangSmith. That is a reasonable commercial model, and it is also a dependency. If you want to avoid it, keep your graph logic free of platform-specific calls and route traces through an open standard where possible.

One more factor is team skill. A graph runtime rewards engineers who think in state machines, while a high-level agent API rewards engineers who think in prompts and tools. Hire or train for the layer your product needs, and avoid forcing a prompt-first team to maintain a forty-node graph they did not design.

Verdict: Use create_agent First, Reach for LangGraph on Purpose

The takeaway: treat langgraph vs langchain as a layering decision, not a rivalry. Both are free under the MIT license, both sit on the same runtime in the v1 line, and both follow the same release policy. The paid part of the stack is LangSmith, which starts at $0 for one seat and 5,000 base traces, then costs $39 per seat for Plus.

Our recommendation rests on data, not hype. Choose 
create_agent
 when your agent loops over tools and you can describe its rules in a prompt. Choose LangGraph when you need approvals, resumable state, strict step order or multi-agent coordination. Choose both when you build a product that grows, because you will start with the first and add the second where failures cluster.

Three dates should drive your schedule. LangChain 0.3 and LangGraph 0.4 lose active support after December 2026. The streaming upgrade to 
langchain-core
 1.7.0 already shipped on October 22, 2026, so mismatched clients are a live risk. And LangSmith’s October 2026 plans are in effect now, so review your trace volume before your next bill.

What we could not verify matters too. No independent benchmark separates the two entry points on speed or accuracy, the customer figures come from vendor pages, and several newer version numbers rest on a single tracker. Run the harness on your own prompts before you commit a roadmap to either layer. If the medians match, and we expect they will, spend your attention on evals, pinning and approval design instead.

FAQ: LangChain vs LangGraph

Is LangGraph replacing LangChain?

No. LangChain v1’s 
create_agent
 is built on LangGraph, so the two libraries work together. LangChain is the higher-level agent framework and LangGraph is the lower-level runtime. Nothing in the November 2026 sources shows either project being retired, renamed or acquired.

Can I use LangGraph without LangChain?

Yes, you can build graphs with LangGraph’s own APIs, and many production flows do exactly that. In practice most teams still install LangChain packages for model integrations and tools, but the graph APIs do not require you to use 
create_agent
.

Are LangChain and LangGraph free?

Both frameworks are MIT-licensed open source with no license fee. You pay for model usage and hosting. LangSmith, the observability and deployment platform, has a $0 Developer tier with one seat and 5,000 base traces per month, and Plus costs $39 per seat per month.

What is the difference between create_react_agent and create_agent?

create_react_agent
 was LangGraph’s prebuilt agent. LangChain v1’s 
create_agent
 replaces it as the recommended standard, and the prebuilt is deprecated rather than removed. Existing code keeps working, but new projects should use 
create_agent
.

Which version should I run today?

Run the v1 line of both. LangChain 0.3 and LangGraph 0.4 are in maintenance through December 2026. The release policy expects minors every one to two months and patches often weekly, so pin exact versions and upgrade clients before servers when streaming changes land.

Does LangGraph support human approval steps?

Yes. LangChain positions LangGraph for human-in-the-loop execution, and the 
interrupt
 primitive with a checkpointer lets a run pause and resume later. Use a durable checkpointer in production so a restart does not lose the paused state.

Is there a performance benchmark comparing the two?

We found no independent head-to-head benchmark. Since 
create_agent
 runs on LangGraph, large speed differences are unlikely, and model latency usually dominates. Measure your own prompts with a fixed model and at least 20 runs per prompt before drawing conclusions.

What does LangSmith cost for a small team?

A team can start at $0 on the Developer tier. Plus runs $39 per seat per month with 10,000 included traces and up to three workspaces, and extra traces cost 0.005 LSU each, where 1 LSU equals $1. Enterprise pricing is custom. Check 
current release news
 for plan changes, since LangSmith repriced self-serve plans in October 2026.

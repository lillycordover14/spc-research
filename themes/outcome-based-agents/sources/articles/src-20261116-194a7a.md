LangSmith now binds every agent to one persistent record spanning deployment tracing evaluation and governance.
Agent type selection auto-configures dashboards so similar agents are measured on identical bases across teams.
Cross-runtime registration lets external OpenTelemetry agents receive the same measurement without adopting one runtime.
 

LangChain
 on November 16, 2026 detailed a rebuild of 
LangSmith
 that gives every registered AI agent a persistent record with a named owner, globally unique immutable ID and type, connecting deployment, tracing, evaluation and governance across runtimes.
LangSmith formerly organized incoming traces by project, without a durable connection to the agent that generated them. Separate environments also produced unlinked pools of telemetry even when they belonged to the same agent. Local, development, staging and production environments now sit beneath one agent ID, with their traces and lifecycle tools attached to the same record.
The redesign is intended to reduce context switching for engineers moving among tracing, monitoring and deployment tools. It also gives platform teams a consistent way to answer ownership, cost and performance questions. Opening an agent record provides one-click access to its traces, evaluations, Agent Server and issues surfaced by Engine.
The architecture expands on the LangSmith Agent Platform introduced in LangChain’s 
November 13, 2026 Series C announcement
, which presented runtime, improvement and governance as three pillars. The new post supplies the data model joining those functions to individual agents.
Agent Types Shape Evaluation
Type determines what appears on an agent’s dashboard, which data connections it supports and how it is evaluated. General-purpose and coding agent types are available, while LangChain lists voice as forthcoming. The planned voice type reflects requirements such as low latency and audio quality in addition to solving a customer’s problem.
LangChain’s examples contrast the initial dashboards. A general-purpose view combines an agent’s description, recent activity, online monitoring, commonly used models and tools, and failures identified by Engine. A coding view instead emphasizes merged pull requests, token cost and categories of completed work; it can also connect to a GitHub repository to track downstream outcomes.
Assigning a type activates a preconfigured dashboard without requiring a team to construct custom views. Because every agent of a given type is measured on the same basis, results can be compared across teams working on similar agents.
Governance Across Runtimes
LangSmith can register agents running on external platforms that support OpenTelemetry Protocol, alongside agents built internally. Registered agents are measured the same way without requiring every team to adopt one runtime. Cost and quality metrics roll up across environments, and the named owner plus detailed traces provide a starting point for investigating a cost spike or performance change.
The platform remains composable. An agent can stay on its existing runtime and use LangSmith’s tracing, evaluation, dataset, annotation and Engine tools once it sends traces to the platform. The agent registry and LLM Gateway add organization-level visibility and controls for registered agents. Teams can instead describe an agent in Studio’s natural-language builder, write code with LangChain’s open-source harnesses or another framework, and deploy on Agent Server.
For customers using both Engine and Agent Server, one integration lets Engine test a proposed fix against a preview deployment before the change is merged into production. That connects diagnosis and verification to the same agent record rather than leaving them in separate workflows.
Availability and Remaining Work
At publication, the rebuilt LangSmith was available globally in cloud, bring-your-own-cloud and self-hosted environments. Centralized dashboards operate at workspace level. LangChain’s roadmap adds organization-level views that aggregate performance and trends across a company, plus identity-provider registration so security teams can manage and audit agents alongside other organizational identities.
LangChain is also connecting existing capabilities (including Engine red-teaming, custom annotation apps, evaluation datasets, trajectory collection and fine-tuning) around the shared record. Its proposed workflow would send reviewed production examples into evaluation datasets and turn trajectories from successful runs into fine-tuning data. Those connections are part of the roadmap; the individual components already exist.
For enterprises managing internally built, vendor-supplied and employee-adopted agents, the rebuild establishes ownership and consistent evaluation as common controls across a mixed fleet. The cross-runtime registry is available, but the broader oversight layer—company-wide dashboards and identity-provider management—remains unfinished.

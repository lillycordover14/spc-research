AMD Contributes Integration For Content-Adaptive / Adaptive Backlight Modulation To GNOME

Written by 
Michael Larabel
 in 
GNOME
 on 20 November 2026 at 12:52 PM EST. 
1 Comment

Merged today to GNOME's Mutter compositor is support for the Adaptive Backlight Modulation (ABM) DRM/KMS connector property and a "content-adaptive" API. This GNOME desktop improvement was contributed by AMD as part of modern AMD Ryzen AI laptops supporting Adaptive Backlight Modulation.
 
Adaptive Backlight Modulation / Content Adaptive Backlight Control is a power-saving display feature for dynamically lowering the display panel's backlight brightness level based upon what is on the screen, such as for dark or low luminance scenes. This in turn can help reduce power consumption for laptops especially on battery life but does come with some impact to the color accuracy.
 
The AMDGPU Linux driver for a while now has exposed the Adaptive Backlight Modulation functionality and the connector property for capable eDP panels.
"AMD eDP panels expose an "adaptive backlight modulation" connector property: the panel dims its backlight and compensates in the image, trading color accuracy for power. This series only adds the compositor side: a content-adaptive level on MetaBacklight, applied to KMS on the next frame.
 
Mutter does not choose a level. The shell is expected to call the C API in-process; there is no D-Bus interface for it. The level is an index in 0..max and defaults to 0 (off). When the connector supports ABM, the first frame writes it, which takes the property over from the driver's sysfs interface. Nothing hands it back on shutdown; that is left to a generic DRM reset."
 
Those curious about this AMD contributed work to GNOME for enhancing the power savings experience with modern laptops can see 
the Mutter merge request
 for all the details.

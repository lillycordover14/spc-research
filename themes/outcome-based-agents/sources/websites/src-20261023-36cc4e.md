We're building Zomma: AI operations employees for finance back offices, starting with cross-border transaction alert investigations.
TL;DR: Zomma agents work directly inside the software your ops team already uses. No APIs, no integrations. For every cross-border alert, the agent gathers the evidence, writes the draft assessment, and drafts the RFI, end-to-end. Running live compliance-ops pilots with a US RIA and a $10B AUM wealth tech. 92% on OSWorld.
https://www.youtube.com/watch?v=oDXDKH_tYhg
Cross-border payments trip more monitoring rules than anything else in the queue: sanctions name hits on foreign counterparties, high-risk corridors, first-time beneficiaries. Most alerts are false positives (McKinsey: over 90% in transaction monitoring), but every one still needs to be investigated. 20 to 60 minutes per case, across five or six systems, several with no API at all. And the evidence that clears them sits in foreign company registries and local-language adverse media.
So review capacity scales the only way it can: hiring. When hiring lags volume, alerts pile into backlogs that take months to clear, and backlogs are what regulators fine: $3.8B in AML penalties last year alone.
Zomma agents work the queue on the same screens your analysts use: case manager, screening tool, admin panel, inbox, web search. Onboarding looks like hiring: an SOP and a login.
On a transaction monitoring alert, the agent
Every step is logged and replayable: timestamped screenshots of every page checked, numbered citations, explicit no-match statements, a screen-by-screen trail an examiner can follow.
If an employee can do it on a screen, Zomma can learn it: the rest of the compliance queue, payment disputes, client onboarding, trade ops. Cross-border alerts come first because they have the exact shape our agents are best at: high-volume, parallelizable work that needs real reasoning but follows a defined workflow to a documented disposition. They're also the hardest cases to automate any other way: the evidence lives in registries and portals that will never have APIs. And agents scale with the queue: a volume spike means provisioning two more that afternoon; a BPO batch takes a month to train.
Computer-use agents only recently got accurate enough to trust with a live queue, which is why we're building this now. Our state-of-the-art computer-use harness with our procedural and workflow memory system scores 92% on OSWorld.
